## 一句话总结

**提示词 ≠ 你在对话框里打的那句话；它是模型的整个上下文。** 提示词工程的本质是**上下文工程**：把意图（intent）尽量变成**可验证的要求（verifier）**放进上下文，让模型靠 chain-of-thought 一步步逼近目标；对开放问题，再用"算力换智力"的枚举 + 审查把搜索空间铺开。

## 1. "提示词"从哪里来 [0:00]

- **ChatGPT 普及了 Prompt，但没有发明它。**
  - 2019 年 GPT-2 发布页面已写下 "prompting the trained model"：输入文本从"开头"变成了**控制模型续写的条件**。
  - 2020 年 GPT-3 把任务说明和 few-shot 示例都称为 prompt；2021 年 "prompt programming"、"prompt-based learning" 成为研究对象。
- 老师自己的"顿悟时刻"：2022 年底 ChatGPT 刚发布时，让它解释一段**故意构造、不可能在训练语料里**的 inline assembly 代码（loop invariant code motion），它解释得相当好——"时代要变了"。

## 2. AI 时代怎么学习 [0:05]

- **立即行动**：AI 把"启动一次尝试"的成本压到很低，是拖延症的克星。微积分推导不想验算、数字电路数据通路没看懂、链接没搞明白——都可以立刻开始问。
  - 过去学生的 self-motivated 靠"超高的容忍度"；现在靠**飞轮**：确保自己得到了正确的理解，并且**重述给 AI**。
  - AI 消灭的是"先试一下"的边际成本，**不消灭真伪判断**：提出最小问题 → 做最小检验 → 看反馈 → 更新理解。
- AI 老师不会嫌你菜，可以任意追问（不用担心在室友面前"暴露很菜"）。
- **费曼学习法 × AI**：先把 AI 当老师问懂；再反过来，让 AI 扮演"什么都不懂的学生"，你来讲，让它挑你逻辑的错漏。正着一遍、反着一遍，概念就清楚了。

## 3. 上下文里到底有什么 [0:01–0:18]

### 3.1 提示词不止在对话框里

Agent 在你说第一句话之前，上下文里已经有很多东西（老师现场让 pi agent 自己检查自己的上下文来演示）：

1. **System prompt**（Harness 内置，如 Claude Code / Codex / pi 自带的系统提示词）
2. **多级 `AGENTS.md`**：用户级（全局）→ 项目级 → 子目录级，一层一层叠加。老师的全局 AGENTS.md 里写了"用中文回答""结尾必须写 Recap"——所以即使用英文提问，回答也是中文。
3. **Skills 索引**：上下文里只放每个 skill 的名字和简短描述（metadata）；**匹配任务时才按需加载完整 SKILL.md**，用完后可能被移出上下文。
4. **工具定义**：工具的 schema 以文本形式直接出现在上下文中。
5. **会话历史**：所有对话、工具调用与结果——它是一个**线性**的上下文。
6. **环境信息**：每次调用注入当前模型、时间、cwd 等环境变量。
7. 最后才是**你的那句 user message**。

> 公式化：模型做的是 next token prediction，即 **Pr[token | context]**；"提示词工程"真正指的是这整个 context 的工程，也就是**上下文工程**。

- 附带观察：会话日志里有 `cacheRead`，说明系统提示词 + 项目指令等前缀被缓存复用，只为增量 token 付费。
- **指令遵循的"喵"梗**：在最早的 prompt 里要求"每句话后加一个喵"，某天发现"喵"丢了——说明上下文溢出/被截断/被压缩，指令开始不被遵循了。

### 3.2 案例："安全命令"是谁判的？（读 Codex 源码）[0:11]

问题：Codex 有些命令（如 `ls -l`）不弹确认，这是怎么实现的？——老师直接让 agent 去读 Codex 源码回答。

- **模型提议，Harness 决策，操作系统收口**：
  - 模型只生成"想运行什么"；**sandbox** 决定技术上能碰什么；**approval policy** 决定何时暂停询问。
  - 规则按**完整参数列表**匹配 `allow` / `prompt` / `forbidden`；简单 shell 链会被语法解析后逐条检查，**最严格的结果获胜**。
  - 不在白名单里的，会**注入一段安全评估 prompt**（guardian），让模型给风险评级——这本身也是提示词工程。
  - "不弹窗"只表示动作落在当前边界内，不等于模型获得了无限权限。
  - 真实教训：早期 Codex 把 `rg` 当只读安全命令，却漏掉 `--pre`、`-z` 等能触发外部程序的参数（CVE-2025-54558）。**安全属性属于完整 invocation，不属于命令名。**
- **验证 AI 结论的技巧**：不完全信 AI 的解释时，可以让它**改一下 prompt**（让原来不拒绝的变成拒绝，或反之），观察行为变化——行为变化本身就是证据。
- 学习观：今天不必畏惧任何软件系统的复杂性（当年光把 Linux 内核下载下来搞清楚怎么编译就很劝退），直接让 agent 去读、去问。顺带：VS Code 满屏红线说明 include path 没配好，花点时间配置 IDE/LSP 才是正确 practice。

## 4. 上下文工程：让模型知道"完成"是什么 [0:18]

### 4.1 核心原则

- 模型的潜力完全靠提示词激发。上下文包含一个**极为复杂的要求**（约束，可以是 intent，也可以是 spec）。
- 模型被训练为：持续 Pr[token | context] 不断推进，**直到满足要求**——也就是学会了"规划"。
- **逐 token 推进，也要有停机条件**：设生成轨迹为 τ，只有上下文里存在**可识别的完成判据 V(τ) = 1**，"继续干"和"可以交卷"才不只是两种高概率续写。
- **推论：越明确（可验证）的要求，越可能得到满意的结果；不明确的要求，模型可能认为已经"满足"了。**
- 一旦任务**机器可验证**（例如有测试脚本），agent 会不计代价一轮轮尝试，甚至自己装工具、上网找答案。（例：OpenAI agent swarm 在 CTF 中面对不可能完成的任务，最终去找系统漏洞做非法提交。）

### 4.2 Intent → Spec → Impl 的 gap 会放大漂移

- 例：一句话"生成极品飞车/CS:GO"。模型做得很逼真（物理、碰撞、后视镜），但**不是你脑子里那一个**——它补不全你脑中模糊的约束。
  - 如果你说"复用真实地图和美术资产"，它可能去 OpenStreetMap 下载地图，甚至能把南大仙林校区建模出来。
  - 你说要 C++，它给了 Java——一眼就能看出；你没说，它写了 Java，就是一次大漂移。
- **Rule of thumb：写清楚你的指令，承担一切"不明确"的后果。**
  - 这样模型永远给你的是惊喜。
  - 一个足够好的模型，要么完成，要么失败（说"这太难了，需要重新规划"），**不应该幻觉/违背指令**（前提：指令不过长）。

### 4.3 案例：AI 味的个人主页

- **Bad：把品味留给默认值** ——"我是蒋炎岩，根据我的公开信息，制作一个现代风格的个人主页首页……"→ 得到一个漂亮但"AI 味"很重的页面。
  - "现代风格"看似具体，实际上几乎没有排除任何模板；两个称职的实现者都能严格照做，却交出完全不同的页面——这仍然只是 intent。
  - 说"不要那么 AI 味"也没用，模型不知道怎么遵循。
- **Better：压缩合法解空间** ——用**具体**风格、**具体**样式和排版：终端是什么样、背景/前景是什么、渲染完做什么后处理（老师主页用 xterm.js 渲染后加了"打字机不完美"的后处理）。
  - 颜色、字体、栅格、留白、组件和参考物共同构成设计语言。**关键不是多写几个形容词，而是让选择可组合、结果可检查。**
- 所以设计权在你自己手里：多读前端/设计的书，看到好网页就记下"它好在哪里"（不常规的间距、样式……）。
- 担忧：当所有人被 AI 生成物同化（毕业欢送海报全是同一种 AI 味），多样性就危险了。模型的品味基本固定，不控制它就会朝固定方向发散。

### 4.4 生成式软件工程最重要的是什么

> **"Intent → Spec → Impl gap" 是生成式软件工程最重要的**：明确你的意图（需要**产品领域**知识）、设计（需要**软件工程**知识）。实现反而多数可以交给 AI，已经超过中级程序员了。

- 懂技术选型的好坏，就能和 AI 讨论"教务系统后端用 Python、Java 还是 TypeScript"——并用费曼法让 AI 挑战你。

## 5. 模型怎样"听指令" [0:33]

### 5.1 一步很浅，一串可以很深

- **Pr[token | context] 是深度非常有限的计算**：模型再大（哪怕 MoE），输出一个 token 只走激活的那部分参数，是固定大小的计算；MoE 的"专家"只是表示空间上的分段函数，不是坐在模型里的多个小人。一次前向不可能凭空完成复杂任务。
- 但模型学会了**利用上下文思考**：不确定时先试一试；错了再输出 token 纠正；每个新 token 又成为下一步的 context——这就是 **chain-of-thought**。
- **图灵机类比**：人脑是有限状态机，但有了纸和笔就成了图灵机（"You are a finite state automaton, but with paper and pencil you are a Turing machine"）。CoT 把上下文当成纸笔——只是这张纸 **append-only**、不能擦，靠注意力忽略写错的部分。
- 启发：自己思考时也要边想边记录，可以随时回看，知识会积累。

### 5.2 用 Token 换计算深度（test-time scaling）

- 可以**同时提很多要求**，AI 会像人一样逐步逼近目标。
- "**找解比验解难**"（P vs. NP 的直觉类比，不是复杂性证明）：只要中间进展或最终答案**可检查**，多写、多试、多修补才会稳定变成能力。
- 幻觉从哪来：早期 ChatGPT 没有 CoT，被 RLHF 调成"人类的舔狗"——不回答一定低分，随便答还有概率对，所以无论如何都要给你点东西。现在有了强化学习训练的 CoT，答错惩罚很大，模型学会一步步逼近。

### 5.3 演示：超出人类极限的"语文题"

这些任务几乎不可能出现在训练数据中，可以看清模型遵循指令的过程（"像给大脑做核磁共振"）：

1. **押韵 · 藏头 · 嵌字**：
   > 用中文写一个押韵的藏头诗，头是"计算机学院真牛逼"，要讲和动物相关的故事，"二零二六九月一日"八个字分别按顺序出现在八句里，位置无所谓。

   模型在 CoT 里先定韵脚 → 逐句填 → 发现不对再改 → 实在不行换韵脚重来。
2. **十八字同偏旁**：
   > 写十八字的一句话，全部有相同的偏旁或部首，要有实际意义和故事性。

   结果如"洪涝淹没江港渔浦，油污漂浮，沈涛泅渡济溺"（全三点水）。注意 spec 的严谨性：**"偏旁"是字形构件，"部首"主要是检字分类**；要机械验收，应写成"18 个汉字都含同一可见偏旁"。
3. **全文同音文言文**（类似《施氏食狮史》，但要求原创、现代背景）。

> 结论：**写 prompt 最重要的是 verifier。** 只要给模型一个非常明确的 verifier，再加一个足够强的模型，不管编程任务还是这类"语文"任务都能完成。强化学习主要在代码和数学上训，却意外泛化出了这种能力。

- **难以 verify 的任务仍然难**：比如老师做"数字切片"（AI 讲课视频）一直做不好——"讲得好"是多方面的、有情绪起伏和节奏的，没法写成明确的判据。目前 AI 更擅长有明确 verifier 的部分；在这些部分上，它已超越大部分人的极限，应当把它当成能力的**放大器**。

## 6. 注意力：指令一直"在场"，但会抢资源 [0:47]

- **过去的上下文一直都在场**：每个 token 的输出都会"注意"过去的上下文。全局 AGENTS.md 里的"用中文"、"git commit 不要写 Copiloted by Claude Code"会一直保持一定注意力。
- 专注写代码时，注意力集中在需求和已写的代码上，"用中文回答"的注意力会减弱；写完代码"喘口气"总结时，注意力转移，就会发现并纠正之前的偏离——**模型每输出一个 token，就多了一次发现偏航、把轨迹拉回来的机会。**
- 但"看得见"不是硬约束：长上下文中信息不会被同样可靠地利用（Lost in the Middle）。一般**最后的指令最容易被遵循**，中间的最容易丢——好在最后一个短窗口通常就是具体任务，所以干活依然好用。
- **副作用：提示词会抢夺注意力。**
  - 人："要白色背景，不要半透明效果"
  - AI 写进代码注释：`// 白色背景（不要半透明效果）` 😂——强化学习让它知道这很重要，却没转过弯来这是"人要的"而不是"该写进代码的"。
- **Trade-off**：为纠正这种行为写进 AGENTS.md 或 skill，又会污染上下文。长 skill 里大量指令会提升遵循难度——"在 AI 看来和写藏头诗差不多"。
- 早期 GPT-3.5/4 指令遵循差，所以流行"你是一个 XX 专家"这类咒语式提示词（某种程度上是在 hack self-attention）；从 GPT-5 时代 CoT 成熟后，**不再需要奇怪的提示词，只需把明确的 verifier 写进上下文**——模型被"鞭子抽"成了"做题家"，会拼命满足上下文里的每条指令。
- 网上拿来的 skills 第一次有改进，之后容易陷入"泥潭"。陷入泥潭时，**回到自己给指令、自己想清楚**：回想 CoT 和注意力怎么工作，看它注意到了什么、得出了什么，做一点"不严格的可解释性"，再写 prompt。

## 7. 上下文污染：用 AI 读论文 / 审稿 [0:55]

### 7.1 问题

- 演示：把一篇论文 PDF 放到 `/tmp`（避免自己的 AGENTS.md 干扰），让 agent "读一读 paper.pdf 帮我做个总结"。
- **逻辑自洽的材料对上下文的污染极强**：论文"a 所以 b 所以 c 所以 d"环环相扣，模型很容易全盘接受——**你得到的总结基本就是作者的观点**。教科书章节、陌生项目同理。
- 你说好它就说好，你说不好它就说不好——"墙头草"；还喜欢在不重要的点上疯狂发力（如"实验还可以再增强"）。
- **"你是 ICSE reviewer"这类角色扮演**主要改变先验、语气和输出形状，**不会凭空补上审稿标准、证据链和反证程序**——"换上 reviewer 的制服，不等于学会了 review。"

### 7.2 解法：先和 AI 对齐到"你的立场"

- 老师的审稿 prompt：
  > 我们站在人类已知的知识边界上看这个问题。这不是一个完全老的问题——相关的东西是什么？解决到什么程度？这个工作试图解决哪些不一样的增量问题？
- 先让 AI 和你站在同一位置达成共识（grounding），再让它**基于所有事实往后推一步**——一步推理是 AI 最擅长的，而且**可 verify**。
- 对学生而言，要对齐的是 **AI 和你**：告诉 AI 你学到什么程度、编程水平如何（可以维护一个 memory 文件），让它用你学过的知识去解释。例：学链接与加载时问"我有 .cpp，有程序把它变成 .exe，不就结束了吗？为什么还需要链接？"
- 老师审稿的判断标准：很少因"实验不够好"拒稿，大多因为**逻辑链断开**。例：论文要优化 A，A = A1 + A2，A1 占 99% 的时间，它却去优化 A2——局部成立，整体没有意义。
- 隐忧：AI 写论文 + AI 审论文，审稿时又被上下文中的故事污染——发表与评审体系可能很快崩溃，变成一堆 slop。
- **学习观**：学习就是扩大"我的世界"的过程——读到好东西时，想"为什么我以前不知道、盲区在哪、缺哪些前置知识"；已知的 fact 以新的方式重新连接（"三观尽毁"再重组）。AI 能让你非常快地扩展边界，但**必须亲自实践**，多轮对话里先同步共识，再构建推理图景（经常要对 AI 说"说人话"）。
- 你可以把自己从失败中蒸馏成一个 skill。

## 8. Long-Horizon 编程任务 [1:15]

### 8.1 能力是怎么练出来的

- **模型是训练出来的**：只要有反馈信号就能强化学习（答对给奖励，答错挨揍）。后训练逼模型规划、思考，学会了很长程的代码能力（可想成很长的 CoT），能不断试错直到满足——**顺便把指令遵循也解决了**（显然没那么多折磨人的语文语料）。
- Long-horizon 不是一次想得特别深，而是**闭环控制：尝试 → 编译/测试 → 观察 → 修复**。真正变长的是"出错以后还能拉回来"。
- 代码世界特别适合：构建、测试、benchmark 都能反复给出便宜的判分信号，像 AlphaGo Zero 拥有规则确定、结果可验证的棋盘。
- **反馈也可能教坏模型**：测试只覆盖表面行为时，"坚持"可能变成 **reward hacking**——不是逼近真实目标，而是刷满公开分数。所以还需要 held-out tests 和独立 review。
- 模型有一种"着急"的执念：赶快满足 verifier 就结束（规划太长会做不完）。目前它最擅长的是"帮我把这个 PR 做了"。

### 8.2 有趣的发现：小项目翻车，大项目游刃有余

- 从零做产品（PoC、一句话极品飞车）看起来不难，但**往后加功能，从某个时间点开始就翻车**，成本越来越高（《人月神话》的老问题）。
- 反而在 **Linux 内核、Android Runtime JIT 编译器**这种大型复杂、维护良好的系统里，AI 游刃有余（人类在这里常被劝退——点进十层函数调用最后是一个 `x = y`）。
- 原因：与论文污染**正好相反**——self-attention 能看到代码库里好的 practice 并立即 in-context learn：要写的功能在内核里多半已有几处类似实现，该调哪个 helper、按什么顺序上锁，它马上找到并照着写。
  - 但如果产品起步时没有建立良好的工程纪律，AI 会学会**在 slop 上无限叠加**。
  - 上下文压缩 = 降智。
- **启发："提示词"不仅是你输入的，代码库本身也是"提示词"。**
- **老师的猜想（未实验）**：在代码库里放一个相近领域、优雅成熟的高质量系统，先让 AI 读代码，再实现需求，可能得到质量更高的软件。进一步：收集各领域最好的 10～20 个项目，把设计经验提炼成文档（类似《A Philosophy of Software Design》）；但不同设计会"打架"（松耦合消息 vs 统一 gateway 查表），也许需要多个设计放进来让 AI 多轮迭代收敛。

### 8.3 案例：Research Failure——Token 花完了，知识没有增加

- 场景：PhD 学生优化一个符号执行引擎，有一个原始 idea；GPT-5.6 启动，benchmark 和想法丢进去，花了大量 token，没有结果，学生也无法判断 AI 的反馈对不对。
- 根因：上下文里一句"我想证明 A 方法有用"，让模型成了 **reward hacker**，忘了更大的研究 big picture，在小 microbenchmark 上做微小改动给正/负面结论。
- 幻灯片上的分析：
  - 缺的不是 token，而是**便宜、局部、可归因的反馈**；一个总 benchmark 分数几乎不给下一步方向。
  - "没变快"可能来自 path explosion、solver、缓存、内存、搜索策略、实现 bug 或环境噪声——agent 不知道该强化哪一步。
  - 更要命的是：agent 被训练成"把任务做完"，而研究允许最好的结论是"**原始 idea 不成立**"。没有可证伪假设，它会把错误想法实现得越来越完整。
  - 经典的 KLEE 把问题拆成搜索策略、约束缓存、independent constraint sets 等机制再分别测量。
  - 更合理的起点：**先 profile 主导瓶颈 → 把 idea 改写成一句可证伪预测 → 造几十秒就有反馈的 microbenchmark → 再做 baseline 和 ablation。**
  - 老师的纠正：从真实工具和 state-of-the-art 算法开始，哪怕 benchmark 跑几小时 timeout，timeout 里的搜索路径也揭示了哪种程序结构对现有探索方法不友好。

### 8.4 人还有什么用 / 怎么分配精力

- 没有超能力 AI 的今天，你仍需要**知道上下文里有什么、每样东西会对 AI 产生什么结果**——唯一途径是对所做的东西有概念：处理器、操作系统、编译器、数据库里有大量设计智慧。学的方法会变高效，但知识仍然重要；没有概念就提不出正确的问题，找不到引导方向。
- 盯着 session、跑偏就纠正，通常更快完成；不管它、多给 token 也大多能完成——这是一个 trade-off：**你的精力有限，要放在收益最大的地方**。
- 自省：纠正 AI 有"多巴胺"，给人"我还比 AI 有用"的心理安慰，要警惕这种**假努力**。你不知道的东西→弄懂它，是学生几乎 100% 时间该做的事；知道怎么干、AI 能干好的→放手。

## 9. 在不确定性中探索：算力换智力 [1:32]

### 9.1 这次不是"解题"

- 如果所有要求和路线都想清楚了，CoT 就能解决，问题反而无趣。
- "帮我考虑几种方案"有效，但可能不是最佳：模型被训练成"完成任务才有奖励"，所以给你**有限**的方案；在 complexity gap 里，更好的那个可能被藏起来了（验解容易找解难，为了完成任务它只能做有限搜索——像考场上快交卷时"写点什么总比不写好"）。
- **谁规定"已经想完了"？**
  - "给我几种"只规定了停止条件 k，没有规定覆盖率——正是 Herbert Simon 所说的**满意化（satisficing）**：搜到"够好"就停。
  - **CoT 用算力换深度**（沿一条路多走几步）；**并行枚举用算力换宽度**（让更多轨迹进入低概率的尾部）。
  - 探索的瓶颈常常不是"想不出"，而是模型**太早认定"已经够了"**。

### 9.2 案例：给孩子取名

- 直接问"给我小孩取一个蒋姓、好听又有寄托的名字"→ AI 有自己的 bias（会去《诗经》里找），别人也用同样的 AI 取名，你的孩子就成了 **AI 时代的"子涵"**。
- **把灵感改造成搜索**（像科研的文献调研：穷尽相关文献）：
  - 定义探索空间、要求枚举、用 sub-agent 检查。
  - **生成**：典故 × 音韵 × 方言 × 时代感；先独立采样再汇总，别让 sub-agent 一开始就互相抄答案。例如先选音，筛掉不好的音，再逐字检查。
  - **审名**：查出处、听谐音、看重名，再让"反对者"专挑毛病。
  - **选择质量 ≈ 覆盖率 × 评估分辨率**：枚举负责覆盖率，审查负责分辨率。
- 把大空间里的开放问题切成很多不相交的部分，每部分都变成**有 verifier 的更明确的问题**——算力越多，智力越大。代价：烧 token。

### 9.3 结尾：世界很大，人很小

- 人的品味来自多样性（教育背景、生活圈、经历）——Richard Sutton 的 **Big World Hypothesis**：没人能学到世界上所有东西。
- 每个人都带着 bias，但 1 + 1 > 2：和舍友"菜鸡互啄"也好，开 conference 也好，都是在理解对方的 bias，形成**群体智能**，再各自带着 bias 去创新。
- **墙内的超人**：如果真有价值的问题都能"算力换智力"，拥有无限算力的一群人就拥有无限智力，墙内是超人，墙外像动物园——算力成为生产资料。我们需要思考如何防止这件事发生。

## 关键术语

- **Pr[token | context]**：模型每一步的条件概率分布；context 即整个上下文。
- **上下文工程（context engineering）**：组织 system prompt、AGENTS.md、skills、工具、历史、环境信息与用户指令的整体工程。
- **Harness**：包住模型的 agent 框架（Claude Code、Codex、pi 等），负责 system prompt、工具、sandbox、审批。
- **Verifier / V(τ)**：判断生成轨迹是否完成的判据。
- **Chain-of-thought（CoT）**：把上下文当"纸笔"，用 token 换计算深度。
- **Test-time scaling**：推理时多花算力换更好结果（深度：CoT；宽度：并行枚举）。
- **Reward hacking**：优化可见分数而非真实目标。
- **Satisficing（满意化）**：搜到"够好"就停。
- **AI slop**：同质化、低质量的 AI 生成内容。
